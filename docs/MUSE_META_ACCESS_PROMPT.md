# Prompt for Muse: KobeOS Meta Access Native App

Copy the prompt below into Muse.

```text
You are a senior full-stack engineer building a production-quality native companion app called “KobeOS Meta Access”. It must connect a merchant’s Instagram Professional account to the existing KobeOS Live Sales backend through Meta’s official APIs. Do not build a scraper, browser automation, or unofficial Instagram connector.

## Existing product and repository

The existing KobeOS repository is a TypeScript/React frontend with a NestJS backend. The repository root is:

C:\KobeOS\app

Relevant existing files and contracts:

- Frontend Live Sales app: src/apps/live-sales/index.tsx
- Backend Live Sales controller: server/src/live-sales/live-sale.controller.ts
- Backend Instagram service: server/src/live-sales/instagram.service.ts
- Live Sales entities: server/src/live-sales/live-sale.entity.ts
- Social account entity: server/src/social-scheduler/social-account.entity.ts
- Backend environment example: server/.env.example

The KobeOS backend already exposes these endpoints. Reuse them; do not create a second competing OAuth implementation:

- GET /api/live-sales/instagram/oauth/url
  Returns { url } for the signed Meta OAuth URL.
- GET /api/live-sales/instagram/oauth/callback
  Public backend callback. It exchanges the code, stores the encrypted/server-side account token, and redirects to the KobeOS frontend.
- GET /api/live-sales/instagram/connection
  Returns the authenticated merchant’s Instagram connection status.
- DELETE /api/live-sales/instagram/connection
  Disconnects the authenticated merchant’s Instagram account.
- POST /api/live-sales/instagram/webhook/subscribe
  Retries the account webhook subscription after Meta app configuration is corrected.
- GET /api/live-sales/public/webhooks/instagram
  Meta webhook verification endpoint.
- POST /api/live-sales/public/webhooks/instagram
  Meta webhook event endpoint. Incoming comments are routed into the existing Live Sales parser, reservation, checkout, stock, order, and reply flow.

The existing session flow is:

1. Merchant connects Instagram.
2. Merchant starts an Instagram Live Sales session in KobeOS.
3. Meta sends Instagram comment/live_comment webhook events.
4. KobeOS parses a buy-code such as “A1 x2”.
5. KobeOS reserves stock, creates a checkout link, and can send a private reply.

## Primary objective

Create a polished native setup and connection app that makes Meta access understandable for a non-technical merchant, while keeping all Meta secrets and tokens secure on the KobeOS backend.

The app should feel like a first-class KobeOS utility, not a generic developer console.

## Critical security rules

1. Never put INSTAGRAM_APP_SECRET, a Meta app secret, or a long-lived user access token in frontend code, native app bundles, logs, analytics, crash reports, or localStorage.
2. The native app must use the system browser to start OAuth against the KobeOS backend endpoint. Do not implement the client secret exchange inside the native app.
3. Keep the OAuth state generated by the KobeOS backend. Do not replace it with a client-generated state.
4. Store tokens only in the server-side social_accounts record or the existing secure server secret store. Mask tokens in all UI and logs.
5. All authenticated status and disconnect requests must use the existing KobeOS authenticated API client.
6. Treat webhook payloads as untrusted input. Validate the shape, ignore unsupported fields, cap text length, and preserve external event IDs for idempotency.
7. Never claim “connected” unless the backend confirms that the OAuth exchange succeeded.

## Native app screens

Build these screens:

### 1. Welcome / connection screen

Title: “Connect Meta to KobeOS”

Explain in simple language:

- Connect an Instagram Professional account (Business or Creator).
- KobeOS will receive comments from an active Live Sales session.
- KobeOS will use those comments to match products and create checkout reservations.
- KobeOS does not receive or store the merchant’s Instagram password.

Primary button: “Connect Instagram”

Secondary action: “Open Meta setup guide”

Show a visible “What access is requested?” section listing only the scopes actually configured by the backend. Do not invent scopes in the native client.

### 2. OAuth progress screen

Show:

- Opening Meta authorization…
- Waiting for permission…
- Returning to KobeOS…

Handle cancellation, denied permissions, invalid state, expired state, and backend errors with actionable text.

### 3. Connected account screen

Show:

- Instagram handle and display name
- Profile avatar when available
- Connection status
- Token expiry warning when available
- Webhook status: Connected, Pending, or Needs attention
- Webhook URL from the backend response, if the backend exposes it

Actions:

- “Retry webhook subscription” calls POST /api/live-sales/instagram/webhook/subscribe.
- “Disconnect Instagram” calls DELETE /api/live-sales/instagram/connection after confirmation.
- “Open Live Sales” navigates back into KobeOS Live Sales.

### 4. Meta configuration checklist

Show a checklist that the operator can complete in Meta for Developers:

- Create or select the Meta app.
- Add Instagram Business Login / Instagram API access.
- Set the exact OAuth redirect URI to the backend callback URL.
- Configure the Instagram webhook callback URL to the backend verification/event URL.
- Set the same verify token in Meta and the KobeOS backend environment.
- Subscribe the app/account to the comments and live_comments fields supported by the current Meta app configuration.
- Use an Instagram Professional account, not a personal account.

The checklist must distinguish between “KobeOS code is ready” and “Meta dashboard configuration is still required”.

## Backend integration requirements

If a backend change is needed, modify the existing NestJS service and controller instead of creating duplicate routes.

Required environment variables:

- INSTAGRAM_APP_ID (the Instagram app ID shown in Instagram API → API setup; currently `1754586998908005`, not the parent Meta app ID)
- INSTAGRAM_APP_SECRET
- INSTAGRAM_REDIRECT_URI
- INSTAGRAM_API_VERSION
- INSTAGRAM_OAUTH_SCOPES
- IG_WEBHOOK_VERIFY_TOKEN
- APP_PUBLIC_URL
- APP_FRONTEND_URL
- JWT_SECRET

The production callback should be:

https://api.kobeapptz.com/api/live-sales/instagram/oauth/callback

The production webhook URL should be:

https://api.kobeapptz.com/api/live-sales/public/webhooks/instagram

Do not silently substitute an Apify URL for Instagram Live. Apify may remain available for ordinary post/reel campaign polling, but it is not the primary Instagram Live connector.

## Event and sales behavior

Support Meta webhook events for comments/live comments according to the current backend contract. Normalize them to:

{
  platform: "instagram",
  accountId: string,
  liveSessionId: string,
  externalId: string,
  buyerHandle: string,
  text: string,
  timestamp: string
}

Do not create orders directly in the native app. Send normalized events to KobeOS so the existing Live Sales service remains the single owner of:

- product matching
- quantity parsing
- stock reservation
- checkout token generation
- order creation
- payment initiation
- audit trail
- private reply text

## Facebook readiness

Design the connection model so Facebook can be added without changing the native app’s security model:

- platform enum: instagram | facebook
- account cards
- platform-specific scopes returned by the backend
- platform-specific webhook status
- shared connection state components

Do not implement Facebook by pretending it is Instagram. Keep its Graph API flow behind a separate backend adapter.

## UX quality requirements

- Responsive desktop and mobile layout.
- Clear loading, success, pending, and error states.
- Accessible keyboard navigation and labels.
- No fake “connected” data.
- No silent catches.
- Copy buttons for redirect URI, webhook URL, and verify-token instructions, but never copy secrets automatically.
- Make it obvious when the merchant must finish setup in Meta for Developers.

## Testing requirements

Add or update tests for:

1. OAuth URL contains the configured redirect URI and signed state.
2. Invalid or expired OAuth state is rejected.
3. OAuth callback stores the account against the authenticated owner from state.
4. Disconnect only removes the current owner’s Instagram account.
5. Webhook GET returns the challenge only for the configured verify token.
6. Webhook POST ignores unknown accounts and unsupported fields.
7. Duplicate external comment IDs do not create duplicate reservations.
8. A valid live comment reaches the existing Live Sales parser.
9. A pending webhook can be retried from the native app.
10. Secrets and tokens never appear in frontend bundles or logs.

## Delivery rules

- Inspect the existing code before editing.
- Preserve unrelated KobeOS features and existing user changes.
- Use the existing API client, authentication, database entities, styles, and build scripts.
- Keep TikTok in a separate connector; do not add an unofficial TikTok dependency while implementing Meta.
- Run frontend typecheck, frontend build, backend typecheck/build, targeted lint, and tests.
- Report every required Meta dashboard setting and environment variable after implementation.
- If credentials are missing, leave a clear setup error and document exactly what the operator must configure. Never use fake credentials or pretend that a live account is connected.
```

## KobeOS values to configure after Muse creates or updates the Meta app

Set these server-side only:

```env
INSTAGRAM_APP_ID=your_instagram_app_id
INSTAGRAM_APP_SECRET=your_meta_app_secret
INSTAGRAM_REDIRECT_URI=https://api.kobeapptz.com/api/live-sales/instagram/oauth/callback
INSTAGRAM_API_VERSION=v24.0
INSTAGRAM_OAUTH_SCOPES=instagram_business_basic,instagram_business_manage_comments
IG_WEBHOOK_VERIFY_TOKEN=use-a-long-random-value
APP_PUBLIC_URL=https://api.kobeapptz.com
APP_FRONTEND_URL=https://kobeapptz.com/
```

In Meta for Developers, use this exact webhook URL:

```text
https://api.kobeapptz.com/api/live-sales/public/webhooks/instagram
```
